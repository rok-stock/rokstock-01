# 게임 설계 — "하루 늦은 모의주식"

게임 규칙의 확정본. 구현과 리뷰의 기준 문서다. 마일스톤별 작업 순서는
[ROADMAP.md](./ROADMAP.md), 데이터 아키텍처 상세는 [market-data.md](./market-data.md) 참조.

## 1. 컨셉

공공데이터포털의 일별 시세는 **다음 영업일 오후 1시**에야 공개된다(T+1). 이 제약을 숨기지 않고
**게임 규칙 그 자체**로 삼는다:

- 시세는 항상 "최근 영업일 종가"다. 실시간 호가는 없다 — 그래서 게임 이름이 "하루 늦은 모의주식".
- 매수/매도는 **화면에 뜬 그 종가로 그 자리에서 즉시 체결**된다. 주문 대기·정산 지연은 없다.

가격 정보 자체는 하루 늦지만 체결은 즉시라, 어제오늘 실시간 급등락을 좇는 단타보다는
**기업을 보고 사는 투자**에 가까운 리듬이 만들어진다. 이것이 이 게임의 교육 목표다.

> **v1(2026-08) → v1.x 개정**: 최초 버전은 "오늘 주문 → 다음 거래일 종가로 익일 체결"
> 방식이었다(미체결 주문을 정산해 다음 날 "체결 결과를 개봉"하는 리텐션 루프). 룩어헤드
> 편향을 원천 차단하려는 의도적 설계였지만, 매번 하루를 기다려야 하는 마찰이 캐주얼한
> 모의투자 게임엔 과했다고 판단해 **즉시 체결로 되돌렸다** — 룩어헤드 편향(아래 참조)을
> 이론적으로는 감수하는 트레이드오프다. 상세 배경은
> [learning/stock-order-execution.md](./learning/stock-order-execution.md).

- 대상: 로그인 없음, 게임 상태는 전부 브라우저 localStorage (초기화 지원)
- 종목 범위: **KOSPI 상장 종목만** (약 950개)
- 초기 자금: **1억 원**

## 2. 체결 규칙 (핵심)

### 룩어헤드 편향, 그리고 이 게임의 선택

데이터가 하루 늦는 게임에서 "최근 종가로 즉시 체결"을 허용하면, 포털이나 뉴스에서 **오늘 급등한
종목을 확인한 뒤 어제 종가로 매수**할 수 있다. 미래를 보고 과거 가격에 사는 무위험 차익이라
백테스팅이라면 성립하지 않는 오류다 — 이를 **룩어헤드 편향(look-ahead bias)** 이라 부른다.

엄밀한 시뮬레이션이라면 이 편향을 막아야 하지만, 이 게임은 **캐주얼한 모의투자 학습 도구**다.
주문마다 하루를 기다려 결과를 확인해야 하는 마찰보다, 그 자리에서 결과를 알 수 있는 즉시성을
택했다 — 룩어헤드 편향을 원천 차단하지 못한다는 트레이드오프를 의식적으로 받아들인 것이다.
개념과 트레이드오프 자체는 [learning/stock-order-execution.md](./learning/stock-order-execution.md)에서
더 다룬다.

### 체결 판정

- 매수/매도는 **주문 시점에 화면(종목 상세)에 표시된 최신 종가**로, 그 자리에서 즉시 체결된다.
- 그 최신 종가는 공공데이터 특성상 항상 "최근 영업일 종가"다 — 실시간이 아니라는 뜻일 뿐,
  체결 자체를 늦추지는 않는다.
- 미체결·정산 대기·취소라는 개념이 없다 — 주문 = 체결.

### 주문 입력 방식

체결가가 주문 즉시 확정되므로 수량도 그 자리에서 정확히 계산된다:

| 방향 | 입력 | 처리 |
|---|---|---|
| 매수 | **금액 지정** ("50만 원어치") | `수량 = floor(금액 / (종가 × (1 + 수수료율)))`, 즉시 매수하고 잔돈은 현금에 남긴다 |
| 매도 | **수량 지정** | 종가로 즉시 매도, 수수료·세금을 뗀 정산액을 현금에 더한다 |

- 금액이 1주 가격(+수수료)에도 못 미치는 매수 주문은 즉시 거부한다(`amount_too_small`).
- 지정가 주문·호가단위·가격제한폭은 v2+ (종가 체결이라 지금은 불필요).

## 3. 수수료·세금 (교육 요소)

`src/lib/game/rules.ts`에 상수로 집약한다. 화면에는 주문 시트와 체결 내역에 **항상 명세를
노출**한다 — "거래할 때마다 비용이 든다"를 체감하는 것이 목적.

| 항목 | 값 | 비고 |
|---|---|---|
| 초기 자금 | 100,000,000원 | |
| 위탁수수료 | 0.015% (매수/매도 각각) | 원 미만 절사 |
| 매도 세금 | 0.15% | 2025년부터 KOSPI: 증권거래세 0% + 농어촌특별세 0.15% (2023년 0.20% → 2024년 0.18% → 2025년 0.15% 인하 연혁 자체가 학습 포인트) |
| 양도소득세 | 없음 | 소액주주 국내 상장주식 비과세 — 개념 카드로만 설명 |

## 4. 게임 상태 (localStorage)

### 키 전략

- **`rokstock:game` 단일 키**에 전체 상태 저장. 매수/매도가 현금·포지션·내역을 **한 번에**
  바꾸므로, 키를 쪼개면 부분 쓰기 실패 시 정합성이 깨진다. 리셋도 키 삭제 한 번.
- 관심 종목(`rokstock:watchlist`)은 게임과 생명주기가 달라 분리 유지.
- `schemaVersion` 필드로 향후 구조 변경 시 마이그레이션한다.

### 스키마 (v3)

```ts
interface GameState {
  schemaVersion: number;     // 3
  startedAt: string;         // 게임 시작 시각 (ISO) — 수익률/벤치마크 기준일
  cash: number;              // 주문 가능 현금
  positions: Position[];     // 보유 종목
  trades: Trade[];           // 체결 내역 (최신순, 상한 500건)
  realizedPnlTotal: number;  // 누적 실현손익 (내역 절삭에도 보존)
  achievements: string[];    // 달성한 업적 id 목록
}

interface Position {
  code: string; name: string;
  quantity: number;
  avgPrice: number;          // 평균 매입 단가 (수수료 미포함)
  totalCost: number;         // 총 매입금액 (평단 재계산 오차 방지용 원본)
}

interface Trade {
  id: string;
  side: "buy" | "sell";
  code: string; name: string;
  quantity: number;
  price: number;             // 체결가 = 주문 시점 조회된 최신 종가
  fee: number; tax: number;  // 수수료 / 농특세(매도만)
  execDate: string;          // 체결가의 기준일 (YYYY-MM-DD)
  settledAt: string;         // 체결 처리 시각 (ISO) — 주문 시각과 사실상 같다
  realizedPnl?: number;      // 매도 시 실현손익
}
```

> v1/v2 에 있던 `lockedCash`/`PendingOrder`/`Position.lockedQuantity` 는 v3 에서 사라졌다
> (즉시 체결로 전환되며 "미체결"이라는 상태 자체가 없어졌다). `store.ts` 의 마이그레이션은
> 남아있던 미체결 주문을 취소된 것으로 간주해 잠긴 현금을 돌려준다.

### 리셋

- 설정 화면에서 2단계 확인 후 초기화. 리셋 직전 **"이번 게임 성적표"**(기간, 최종 수익률,
  거래 횟수, 낸 수수료 총액)를 보여준다.
- 관심 종목은 기본 유지, "관심종목도 초기화" 체크박스 제공.
- 레버리지가 없어 파산(음수 자산)은 불가능 — 강제 파산 규칙은 없다.

## 5. 화면 구조 (모바일 우선)

| 라우트 | 내용 |
|---|---|
| `/` | 홈: 총자산·수익률 카드 → 보유 종목 → 관심 종목 |
| `/stocks/[code]` | 종목 상세: 차트 + 보유 현황 + 리포트 탭(G6) + 하단 매수/매도 바 → 주문 바텀시트(즉시 체결) |
| `/history` | 체결 내역(수수료/세금/실현손익 명세) |
| `/settings` | 게임 정보, 초기화, 데이터 안내("T+1 13시 갱신") |

- 하단 고정 3탭: **홈 / 내역 / 설정** (safe-area 대응). 검색은 기존 상단 헤더 유지.
- 색 관례: 상승 빨강 / 하락 파랑 (기존 `format.ts` 유지). 매수 버튼 빨강, 매도 버튼 파랑.

## 6. 데이터 아키텍처 요약

상세는 [market-data.md](./market-data.md). 핵심만:

- **시드 데이터**(로컬 생성 → 커밋): KOSPI 종목 마스터(+법인등록번호), 최근 5영업일 전 종목
  시세, KOSPI 지수 1년. 튜플 포맷 JSON, raw 약 420KB.
- **런타임**: 전 종목 스냅샷 1회 페치(`mrktCls=KOSPI&numOfRows=1000`)가 시세의 단일 진실
  공급원. 검색은 시드 로컬(API 0회). API 실패 시 시드 fallback.
- **ISR**: 페이지 `revalidate 3600` + fetch 태그, Vercel cron(13:20 KST경)이
  `/api/revalidate`로 온디맨드 재검증. 일일 API 호출 200회 미만(한도 10,000의 2%).

## 7. 교육·재미 요소 우선순위

**v1 내장 (G2~G5)**
1. 수수료/세금 명세 상시 노출
2. 온보딩 카드: "왜 하루 늦은가?" 규칙 3장
3. 매수/매도 즉시 체결 토스트 (체결가·수수료·실현손익 즉석 확인)
4. 평가손익 vs 실현손익 구분 표시

**후속 (G6~G7)**
5. 기업 리포트 (요약 재무, PER/PBR)
6. KOSPI 벤치마크 비교 ("지수에 묻어뒀다면?")
7. 업적 (첫 매수 / 분산투자 5종목 / 존버 30일 / "수수료로 치킨 한 마리")
8. ConceptTip 용어 카드

**v2+ 아이디어**
- 지정가 주문 + 호가단위 + 가격제한폭
- 일일 자산 스냅샷 → 내 수익률 곡선 차트
- ETF 지원 (증권상품시세정보 API 추가 신청 필요)

## 8. 데이터 출처와 라이선스

| 용도 | API (공공데이터포털) | 비고 |
|---|---|---|
| 시세 | 금융위원회_주식시세정보 | 이용허락범위 제한 없음 |
| 종목 마스터 | 금융위원회_KRX상장종목정보 | 〃 (crno = 재무 조인 키, 우선주는 시세와 병합) |
| 지수 | 금융위원회_지수시세정보 | 〃 (2020년 이후 데이터만) |
| 기업 리포트 | 금융위원회_기업재무정보 + 기업기본정보 | 〃 |
| 배당 (G6) | 금융위원회_주식배당정보 | ⚠️ 공공누리 제2유형 |
| 발행·액면가 (G6) | 금융위원회_주식발행정보 | ⚠️ 공공누리 제2유형 |

- 인증키는 `DATA_GO_KR_SERVICE_KEY` 하나로 공용, API마다 활용신청(자동승인) 필요.
- **배당·발행정보는 공공누리 제2유형(상업적 이용금지)** — 이 프로젝트는 비상업(개인 학습용)
  게임이라 사용한다. 수익화를 검토하게 되면 한국예탁결제원 정보이용계약을 먼저 확인할 것.
