# 총자산과 수익률 — 무엇을 기준으로 잴 것인가

## 개념

### 총자산

```
총자산 = 예수금(현금) + 주문에 묶인 금액 + 주식 평가금액
```

주식 평가금액은 **최근 종가 × 보유 수량**이다. 실제 증권사 앱의 "평가금액"과 같은 개념인데,
이 게임은 T+1 데이터라 "어제 종가 기준 평가"라는 점만 다르다. 주문에 묶인 금액(미체결
매수 예산)도 내 돈이므로 총자산에 포함한다 — 빼먹으면 주문을 넣을 때마다 총자산이
출렁이는 이상한 화면이 된다.

### 수익률의 기준 (분모 문제)

수익률은 "무엇으로 나누느냐"에 따라 전혀 다른 숫자가 된다:

| 기준 | 계산 | 특징 |
|---|---|---|
| **초기 자금 대비** (이 게임) | (총자산 − 1억) ÷ 1억 | 단순·직관적. 입출금이 없는 게임이라 가능 |
| 투입 원금 대비 | 실현손익÷매도원금, 평가손익÷매입원금 따로 | 종목별 성과 보기엔 좋지만 합산이 애매 |
| 시간가중수익률(TWR) | 기간별 수익률의 기하평균 | 입출금 영향 제거 — 펀드 성과 비교용 |

실제 계좌는 입출금이 섞여서 "초기 자금 대비"가 불가능하고, 증권사 앱들이 저마다 다른
기준을 써서 수익률이 앱마다 다르게 보이는 일이 흔하다. 이 게임은 입출금이 없으니
가장 정직한 기준(초기 자금 대비)을 쓸 수 있다 — **게임 전체 손익에는 수수료·세금까지
전부 반영**되어 있다는 뜻이기도 하다.

### 원본과 파생의 분리 (웹개발 관점)

평가금액·수익률을 상태로 **저장하지 않는다**. 시세가 바뀔 때마다 저장값을 고치는 대신,
원본(게임 상태 + 시세 스냅샷)에서 매번 계산한다:

```
evaluatePortfolio(state, quotes) → { totalAssets, totalPnlRate, positions[] }
```

저장하는 값이 적을수록 어긋날 수 있는 값도 적다. React 로 치면 "derived state 는
useState 가 아니라 렌더 중 계산"과 같은 원칙이다.
